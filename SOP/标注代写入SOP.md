# 足球标注质检 + AI 代写 SOP（可复用）

> 沉淀自 migu_1014 项目（Label Studio 多机位足球赛机器标注质检），2026-10-24/25 完整跑通 cam4、cam3 两镜头后总结。
> 适用场景：凉白开（机器预测）已有原始检测，但号码/框有误差，需要「AI 接管大部分、人只判异常」的质检+代写流水线。

---

## 一、任务本质

Label Studio 里每个「帧」是一个 task，机器预测（凉白开）已预标了球员框 + 球衣号码，但存在三类问题：

1. **漏检/多检**：有的球员没框、有的误识别框。
2. **号码错/无号**：框在、号码标错或没标。
3. **串号**：贴身球员（如 58/19）框分离后号码交换。

目标：以「已标注帧」为基准，用 v8b 引擎逐帧链式修正，把机器预测变成高质量标注；人只在关键切换点/异常点核验。

**核心原则（用户明确偏好）**：
- 全程只读不瞎改，代写走 POST/PATCH 且防重复。
- AI 接管大部分机械活，人只判「异常 + 切换点」。
- 拒绝批量下载大数据，交付要「立即可用的工具 + 简短说明」。

## 三、关键口径（每个机位先确认）

| 项 | cam4 | cam3 | 说明 |
|---|---|---|---|
| task_id 偏移 | 帧号 + **33367** | 帧号 + **3367** | **各机位不同，先查** |
| inner_id 偏移 | — | 帧号 − 4499 | 用户搜索用 inner_id |
| 帧号范围 | 4500~11999 | 4500~11999 | 每机位 7500 帧 |
| 坐标 | LS 百分比 0–100 | 同 | 帧间匹配阈值 6 个百分点 |
| label | teamA/teamB/goalkeeperA | teamA/teamB/**goalkeeperB** | 守门员标签可能不同 |

**确认 task_id 映射的方法**：拉任意 task，看 `data.frame` 字段 vs `id`，差值就是偏移。

**号码解析注意**：号码存在 `textarea`(value.text) 或 `number`(value.number) 两种类型，解析时**两种都要匹配**，否则会把 number 类型的号误判成「无号」。

## 四、标准作业流程（代写一批，10 步）

### 第 1 步：确认任务
用户指令格式：「以 N 为基准跑到 M」（正向）或「…之前这段跑错了，位置参考用凉白开的」（重跑）。
→ 明确：机位、基准帧 N、区间 (N+1)~M、方向（正向/倒序）。

### 第 2 步：拉数据
拉基准帧 N + 目标帧 (N+1)~M 的 task，每帧取：
- `ann`：非取消标注（含 annId + result）
- `pred`：最新凉白开预测（result）

保存成 `数据/<cam>_raw_<N>_<M>.json`，结构 `{帧号: {id, ann:{id,result}|None, pred:{result}|None}}`。

### 第 3 步：检查基准帧
打印基准帧 N 的每个框：`label#号码 @(cx,cy)` + 框数 + 号码集。
**确认口径**：这一批要继承的号码集是什么（几个框、双号、门将）。

### 第 4 步：检查目标帧状态（防重复！）
逐帧看 `ann` 是否已有标注：
- 全新（无 ann）→ 后面 POST。
- 已有（有 annId）→ 后面 PATCH，或跳过。
- **多标注**（>1 个 ann）→ 先跟用户确认删哪套。

⚠️ 教训：必须**写入前重拉最新数据**确认 annId，否则会和用户手动标注撞车（曾发生重复标注）。

### 第 5 步：改引擎
复制 `correct_v8_gate.py`，改 4 处：
```python
RAW = .../raw_<N>_<M>.json
prev_boxes = parse(RAW['N']['ann']['result'])   # 基准帧
for f in range(N+1, M+1):                        # 区间
src = fr['ann'] or fr['pred']                     # 有标注用标注，否则凉白开
```

### 第 6 步：跑引擎
```bash
python3 数据/<cam>_correct_<N+1>_<M>.py
```
链式传递：每帧用上一帧修正结果做基准。输出日志含每帧「起稿 X 框 → 修正后 Y 框」+ 动作（删/补/号/签）。

### 第 7 步：核验 payload
核对每帧号码集是否 == 期望口径（全号、无缺失、无多余）。异常 = 框数不对 或 号码集不对。

### 第 8 步：写入
- 全新帧：`POST /api/tasks/{taskId}/annotations`，body `{result:[...]}`。
- 已有帧：`PATCH /api/annotations/{annId}/`。
- header：`Cookie + Content-Type + X-CSRFToken + X-LSFI:1`。
- 大批量（>100 帧）用后台任务跑，`run_in_background`。

### 第 9 步：验证
抽查几帧（起点/中点/终点），确认线上号码集正确、无串号。

### 第 10 步：记录 + 记忆
- 写 `数据/代写入记录/<cam>-NNN_说明.md`（帧号级动作 + 累计数）。
- 更新 `.workbuddy/memory/YYYY-MM-DD.md`（append）+ `MEMORY.md`（长期口径）。

## 五、引擎规则（v8b，已定稿）

1. **两阶段匹配**：第一轮「同号+同标签」绝对优先；第二轮「全局贪心按距离最近优先认领」（防止左侧远框抢号——88 号教训：真实框 0.169 输给误识别框 2.988）。
2. **CLAIM_TOL = 2.0**：身份框位移超门槛 = 误识别框 → 删 + 补框落到上一帧位置，**禁止直接补号**。
3. **删**：unknown 框、无号框、上一帧无对应的框、重复框（同位置已有）。
4. **补号**：无号框 → 上一帧同位置框的号码。
5. **补框**：上一帧有、本帧缺 → 贴上一帧位置补（v5 规则；v6 插值补框**已弃用**——框子容易跑飞）。

## 六、常见坑（踩过，务必记）

| 坑 | 表现 | 对策 |
|---|---|---|
| CDP targetId 会变 | cdp.js 输出空 | `curl http://127.0.0.1:9222/json` 找 Label Studio 页的 id |
| 重跑未重拉 annId | 重复标注 | 第 4 步强制重拉 |
| 球员出画，引擎还补框 | 「幽灵框」一路贴边 | 写入后提醒用户核验出画点，删幽灵框 |
| 跨队同号（双7/双19） | 串号 | 同号**必须同 label** 匹配 |
| number vs textarea 号码 | 误判「无号」 | 解析两种类型 |
| 列表接口 annotations.result 不可靠 | 部分帧框数=0 | 关键帧用单帧接口 `/api/tasks/{id}` 核对 |

## 七、质量核查（整镜头收尾时）

1. **全量进度核查**：分页拉 `/api/projects/{pid}/tasks`，统计「已标注 / 未标注 / 多标注」，输出未标注区间 + 多标注帧。
2. **号码串号排查**：逐帧位置对齐凉白开，找「位置一致但号码不同」，尤其贴身对（如 58↔19）。
3. **镜头切换分镜报告**：按号码集恒定分段，标注每段起止 + 号码集 + 切换原因（+号进场 / -号出画），标状态（已完成/未完成）。
