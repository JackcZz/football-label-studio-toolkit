# LS 帧检助手（Frame Inspector）v1.7

挂在 Label Studio 页面上的 Chrome 侧栏插件：**点哪一帧，就出那一帧的标注信息 + 前后帧对照**；并基于前后帧给出**修正建议**——画布上叠加半透明错位建议框，你点头确认后才写入平台。专为人工审核机器识别结果设计。

适配平台：`http://58.247.144.181:18099`（Label Studio，项目 migu_1014_cam4 等项目通用）。

---

## 1. 它能帮你做什么

打开任意任务（帧）时，屏幕右侧弹出「帧检助手」面板：

| 区块 | 内容 |
|---|---|
| **AI 修正建议** | 据前后 N 帧（默认 5，可调 1-10）加权投票推断：补号（绿）/ 改号（橙）/ 补框（紫）/ 删框（红）。**每条都标出目标框的坐标（@x%,y%）**，配「定位」按钮 + **鼠标悬停自动在画布高亮该框**——应用前就能确认要改的是哪一个；当前帧明细表里对应的框也会打「待处理」红标 |
| **画布叠加层** | 建议框以半透明 + 轻微错位的方式画在原图上，和原框同时可见；rAF 实时跟随缩放/滚动，不错位 |
| **点击定位** | 点面板里任何建议或框行 → 画布上闪圈 + 十字线直接标出位置（查看窗里还会自动放大到该处） |
| **独立查看窗** | 「查看窗」按钮新开窗口：加载该帧图片，canvas 绘制原框 + 建议框，滚轮缩放（以鼠标为中心）/ 拖拽平移，建议可直接应用 |
| **当前帧明细** | 每个框的队别 / 球衣号码 / 中心坐标(x%,y%) / 宽高；缺号框黄色高亮 |
| **质检提示** | 缺号几个（哪些队）、本帧号码重复、队别严重失衡（一边 0 检出）、框贴边（边缘离场？） |
| **机器 vs 人工** | 两个版本并存时，直接列差异（仅人工有 / 仅机器有 / 号码不同） |
| **上一帧 / 下一帧** | 同样明细 + 与当前帧的差异：`上帧有当前无`（疑似本帧丢框）、`当前新增`（疑似上帧漏检）、`号码变化` |
| **运动连续性** | 当前帧 vs 上一帧同位置框的**位移/面积对比**：差距小=正常移动，差距大=异常。位移 >3% 记「跳变」、>1.5% 记「偏快」、面积变化 >40% 或同位置换号也记异常；两级匹配（紧 6% + 松 20%）保证大跳变也能抓出来；点条目直接在画布定位 |
| **复制摘要 / 翻帧** | 一键复制本帧结论文本；◀ ▶ 按钮或键盘 ← →（可关）；帧号不连续自动提示 |
| **跳到帧** | 面板里输入框直接填帧号回车，**不用再滚左侧列表**；已登记过的帧瞬跳，没登记的有界搜索（最多 16 页 ×100 条）后跳转；跳转后左侧列表**自动滚动到目标帧并红框高亮** |
| **下一个未提交** | 状态条显示本帧是否已提交（对应左列表 0/1 列）+ 向后最近的未提交帧号与距离，点按钮**一键跳过去**；未知状态的帧会有界探测（≤25 个 task） |
| **帧号导航条** | 面板顶部一条当前帧 ±8 的连续帧号条：蓝色=已登记点击直跳，灰色虚线=未登记（点击走搜索），黑色=当前帧。**专治左列表乱序**——LS 左列表按 task id 排序，与帧序无关（如帧 5204 左右可能是 4529/4530），导航条按帧号连续排列 |
| **列表排序按钮** | 一键点 LS 的 frame 列头，把左侧列表改成按帧号排序（再点一次反转） |
| **可拖拽** | 常驻标志在**左上角**（不挡右下角提交按钮），可拖动；面板按住**头部**或「⠿」手柄拖动，双击头部复位；位置跨页面保持 |

### 建议类型与判定规则（人工确认帧≈权威）

视频逐帧切换，相邻帧画面差异极小。权重按**来源**分级：

| 帧类型 | ±1 帧权重 | ±2 | ±3 | ±4 | ±5 |
|---|---|---|---|---|---|
| **人工确认帧 · 前侧** | **0.99** | 0.90 | 0.84 | 0.78 | 0.72 |
| **人工确认帧 · 后侧** | 0.80 | 0.62 | 0.52 | 0.46 | 0.42 |
| 机器预测帧 · 前一帧 | **0.75** | 0.06 | 0.02 | 0.01 | 0.005 |
| 机器预测帧 · 后一帧 | 0.17 | 0.03 | 0.01 | 0.005 | 0.003 |

> 前一帧占绝对主导（机器帧约 75%、人工帧约 99%），更远帧迅速衰减；只有后一帧支持时最高只给「中」。

| 类型 | 颜色 | 触发条件 | 置信度 |
|---|---|---|---|
| 补号 | 绿 | 本帧某框缺号，同位置框的号码加权投票 ≥0.4 | 高（≥0.4）/ 中（≥0.1，远帧弱证据） |
| 改号 | 橙 | 本帧有号，同位置号码加权投票结果不同 | 高 / 中；**当前帧是人工确认的不提示**（不擅改人工值） |
| 补框 | 紫 | 前侧、后侧都有相邻帧背书；只有一侧的是进场/退场不补；当前帧是人工时还要求至少一帧人工证据 | 高 |
| 删框 | 红 | 当前帧非人工 + 加权"存在证据"占比 <0.35 | 高（<15%）/ 中；**人工确认帧说没有 → 机器帧说有也提示** |

读取来源优先级：**本地修正 > 最新人工标注（按 updated_at，跳过已取消）> 最新机器预测**。面板来源下拉会显示每份标注的"更新于"时间，诊断区显示本帧数据指纹（各框号码），方便核对插件读的是不是您最新提交的那份。

## 2. 安装（3 步）

1. 解压 `ls-frame-inspector.zip` 得到 `ls-frame-inspector/` 文件夹（放到一个固定位置，别删）；
2. Chrome 地址栏输入 `chrome://extensions` → 右上角打开 **开发者模式** → 点 **加载已解压的扩展程序** → 选择该文件夹；
3. 用**同一个 Chrome** 登录 Label Studio，打开项目数据页，点左侧任意一帧 → 右侧出现面板。

## 3. 数据来源与新鲜度（重要）

- **每次点开一帧，当前帧 + 紧邻的前后各 2 帧全部直连平台重新拉取**（不走缓存），更远的帧才用缓存/页面已加载数据——判断依据永远最新；
- **您改过的帧（插件写入或 LS 里提交）10 分钟内一律不走缓存**；一旦检测到平台发生写入，页面列表带来的所有 task 副本立即作废；
- **重复点同一帧也会刷新**：插件监听左列表点击 + LS 自身的数据拉取/写入，防抖 800ms 后重载面板——您在 LS 里改完再点回来，最多 1 秒自动跟上；
- **您在 LS 里提交/更新标注** → 插件监听到平台写入，自动失效相关缓存并刷新当前帧；
- 一旦发现 LS 重新拉取过某个 task，其缓存副本立即作废重取；
- 本地修正层带时间戳：如果某帧的平台数据比你本地修正更新，**平台优先**并自动弃用本地层。

## 3.5 跳转行为（保守模式）

- **绝不整页跳转/刷新**：找不到列表行时只提示「请在左侧列表手动点它」，不会再出现"刷新后选区乱套"；
- 翻帧 ◀ ▶（以及 Alt+← / Alt+→）：只点**当前视口内可见**的相邻行；行不在可视区就提示，不会自动拽列表；
- 帧号导航条 / 跳到帧输入框：**按可见行的帧号范围和行高，一次性算出还差多少行、直接滚到位**（每滚一步只等 60ms 就检查，目标一进入可见范围就停下并点击）；滚过头会自动反向并缩小步长；**你中途滚轮或按下列表会立刻暂停查找**（控制权还给你）；
- 打开页面/跳转后只有在目标行**不在视口内**时才滚动定位，不跟你的手动滚动打架；
- 方向键默认关闭（避免和 LS 自己的按键冲突）：需要裸方向键翻帧时点面板底部「方向键翻帧」开启。

## 4. 写入后的行为

- 点「应用 / 全部应用」→ 写入平台 → **不整页刷新**；
- 插件自动重拉当前帧重渲染（面板/叠加层立即显示修正后状态）；
- 同时尽力触发 LS 自己的预览刷新（点击当前帧的列表行，SPA 行为，不重置页面、不丢滚动位置）；
- 若找不到列表行，平台数据也已更新，下次打开该帧自动刷新。

## 4.55 模拟人工操作（实验）

每条建议右侧除了「应用」（接口写入），还有实验按钮：

| 按钮 | 行为 | 适用 |
|---|---|---|
| **模拟删** | 在画布上按坐标唯一定位该框 → 派发 pointer/mouse 事件选中 → **确认选中后才按 Delete** → 点 LS 自己的提交/更新按钮 | 标注编辑器里（走 LS 自己的状态，不会被草稿覆盖） |
| **模拟改** | 同样选中框 → 在右侧区域面板找到号码输入框 → 用原生 setter 写入（触发 React input）→ 点提交 | 同上 |

安全设计：**选区没确认就绝不按 Delete**（宁可什么都不做）；找不到输入框/提交按钮会明确提示并放弃；所有动作记入诊断日志。

局限：合成事件对 React 不一定生效（选区类名/结构变化就会放弃）；多框重叠时不做定位。日常批量仍建议用「应用」（按框 id 精确写入 + 写完核对平台）。

## 4.6 原始数据基线（本地存档）

- 每帧**第一次被打开时**，插件把平台上的原始框数据存进本地（chrome.storage.local，跨会话保留）：**队别 / 号码 / 位置 / 宽高**，不存图片；
- 基线一旦建立不再覆盖（基线 = 最早见到的状态），是退回和核对的参照；
- 面板底部「**导出基线**」按钮 → 下载 `lsfi_baseline_<项目>_<日期>.json`，可长期留档（每帧一行，含全部框的坐标与号码）；
- 容量：默认最多保留 3000 帧（按时间淘汰最旧的）。

## 4.7 写入后画面为什么需要等一下

- 插件的写入是**平台接口级**的（等于完成删除/补框/改号并提交），比模拟点击可靠——不会点错框、不会把旧状态又提交回去；
- 写入后插件会**强制 LS 预览重新渲染**（先点相邻行再点回当前行，因为 LS 对"重复点同一行"不响应），画布上多出来的框随后消失、补的框出现；
- 若当前行不在可视区，插件不做任何滚动/点击，只提示「预览未自动刷新，请手动点一下该行」。

## 4.5 退回（撤销修改）

- 每次**首次**修改某帧前，插件在本地快照该帧的**原始数据**（chrome.storage.session，关浏览器即清）；
- 该帧被改过后：提交状态条出现「**↩ 退回本帧（N 处）**」按钮；面板底部「修改历史」列表也可逐帧退回；
- 退回 = 把原始数据写回平台（我们新建的标注则删除），本地修正层同步清理，画布与预览恢复原状；
- 退回只影响该帧，不影响其他帧。

## 4. 回写说明（重要，请先读）

「应用」会把修正**写入该帧在平台上的标注数据**，这是对平台的写操作，规则如下：

- **只写你当前看的那一帧**，一次写操作对应一次确认（单条应用或全部应用前都有确认框，弱证据建议会单独警示）；
- 该帧**已有人工标注** → 更新那份标注（PATCH `/api/annotations/{id}`）；**没有人工标注** → 基于机器预测新建一份标注（POST，字段名从项目配置解析）；
- **机器预测（凉白开等）永远不被修改**，只修改人工标注层；
- 写入成功后面板提示「已写入 ✓」，默认 1.2 秒后自动刷新页面（可取消勾选「写入后自动刷新」手动刷）；
- **不要在 Label Studio 编辑器里同时编辑同一帧**——两边同时改会互相覆盖；
- 写入走平台标准 API（带 CSRF Token），与你在页面上提交标注等效；若平台返回 403/400，面板会原样提示。

## 5. 工作原理

```
document_start 注入：拦截页面自身对 /api/projects/<id>/tasks 的请求（fetch/XHR），
                     登记「帧号 → task id」映射（零额外请求，只用 LS 已加载的数据）
URL 监听（LS 是 SPA，点列表行会改 ?task= 参数，400ms 轮询兜底）
   └─▶ fetch /api/tasks/{当前id}
          └─▶ core.js 解析：rectanglelabels(框+队别) 与 textarea(号码) 按相同 id 配对
                 ├─▶ 前后帧按「帧号±1」从登记表定位 task id，再按需 fetch（绝不按 task id±1 猜）
                 ├─▶ 帧间匹配（同队别 + 中心距 ≤6 个百分点）→ 差异/质检提示
                 ├─▶ suggestFixes：据前后帧生成 补号/改号/补框/删框 建议
                 │      └─▶ SVG 叠加层画在页面主图上（半透明错位，随滚动/缩放跟随）
                 └─▶ 确认后 buildCorrectedResult 生成新 result → PATCH/POST 回写
```

- 坐标为 Label Studio 百分比口径（0-100）；
- **task id 是全平台全局分配的，和帧序无关**——前后帧一律按帧号±1 定位；定位不到会明确提示「未定位」，而不是猜一个错的给你；
- 证据来源：每帧优先取人工标注，没有则取最新机器预测；
- 多预测版本或多人标注时，面板顶部可切换显示来源。

## 6. 已知限制

- 必须在该 Chrome 登录平台（未登录时面板提示 HTTP 401）；
- 帧间匹配按「同队别 + 位置就近」，**相邻球员贴近（同号或异号）时不保证可靠**——建议仅供对照，判断权在你；
- 叠加层按页面主图的当前位置绘制，**主图被缩放/平移后可能有偏移**（刷新或还原缩放即恢复）；
- 翻帧是整页跳转（`location.href`），每跳一次约 1-3 秒；
- 前后帧按 task id ±1 推断，若平台任务 id 与帧序不一致，会提示帧号不连续（以面板显示的帧号为准）；
- 前后帧定位依赖左侧列表**已加载**的页：直接输 URL 打开某一帧、或相邻帧还没滚动到时，面板会提示「未定位」——在左侧列表翻页/滚动，或直接点相邻行即可恢复；
- 「跳到帧」搜索是有界的（≤16 页 ×100 条，约 1-2MB）：已登记帧瞬跳；首帧升序时按估算页码就近探测（通常 1-3 页命中）；若平台返回顺序不按帧号，可能搜不到，面板会明说；
- 目前只适配 `58.247.144.181:18099` 和 localhost；换平台需改 `manifest.json` 里的 `host_permissions` 和 `content_scripts.matches`（加一行域名即可）。

## 7. 装好后没反应 / 算法没更新？按这个顺序排查

> **v2.0.1 起有后台看守**：每分钟核对已打开的平台标签页里运行的脚本版本，发现旧脚本（比如您点了扩展刷新图标但页面没重载）会**自动重载该标签页**——点完 ↻ 最多等 1 分钟，页面自己就刷新生效了，不用您记着手动 F5。
> **左上角常驻标志永远带运行中脚本的版本号**（如「帧检助手 v2.0.1 · 帧 5205」）——版本不对就是脚本旧了。

1. 点 `chrome://extensions` 里扩展的**刷新图标 ↻**（后台看守随后自动处理已开的标签页；也可直接 F5 立即生效）；
2. **看左上角标志**：应显示「帧检助手 v2.0.1 · …」——版本号是判断插件是否真的刷新了的唯一硬证据；
3. 标志版本旧 → 等 1 分钟（看守自动重载），或手动 F5；仍不动 → 检查是否加载了旧文件夹拷贝 / 多个扩展副本；
4. 有标志但点帧不出面板 → 点面板底部**「诊断 → 复制」**，把内容贴给开发者；
5. 标志变黄「⚠ 请按F5」→ 页面脚本比扩展旧，按 F5；
6. 面板提示 HTTP 401 → 该标签页没登录，先登录再刷新；
7. 叠加层位置偏了 → 主图被缩放/平移过，还原缩放或刷新页面。

## 8. 文件清单

| 文件 | 作用 |
|---|---|
| `manifest.json` | MV3 扩展清单（权限仅 storage + 目标站点） |
| `core.js` | 纯函数：解析 / 帧间对比 / 质检 / 修正建议 / 回写数据生成（可在 Node 下单测） |
| `content.js` | 侧栏面板（Shadow DOM、可拖拽）、按需请求、缓存、翻帧、叠加层、确认回写 |
| `test_core.js` | 核心逻辑单测，`node test_core.js` → 28 项断言 |
