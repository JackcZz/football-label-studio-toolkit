## 2.13.0（当前 · 数据源一致性 + 证据链）

**起因**：6129/6130 帧——插件说"人工确认帧同位置号码为 46/3"，用户翻前后帧却找不到这些框；还有框（如 b46）本该提示缺失却没提。根因是**插件读的数据 ≠ 用户眼睛看到的数据**：

**修复（数据源一致性）**
- **草稿与标注按时间竞争**：草稿比最新标注新 → 以草稿为准（用户在编辑器里改完没点 Submit，改动只在草稿上；旧逻辑"标注恒优先"导致插件读旧标注、用户看新草稿，两边对不上）。
- **草稿解析后 human=true**：此前草稿被误标为机器帧，邻帧权重、人工权威全被降权。
- **本地修正层失效判断**：从只看 `annotations[0].updated_at` 改为看"最新标注与最新草稿的更晚者"——用户在 LS 里手动改过（哪怕没提交）就会正确弃用本地层。
- **写入目标跟随读取来源**：读的是草稿 → PATCH 该草稿（`/api/drafts/{id}`，保持未提交状态，用户自己点 Submit）；读的是标注 → PATCH 标注（原行为）。杜绝"按草稿算的建议写进标注"导致框 id 对不上。
- 面板头部来源标注区分「草稿·未提交 / 人工标注 / 机器·xx」。

**证据链（可直接核对）**
- 补号/改号建议新增一行灰色小字：**证据：帧6128 teamB#46@(82,43) 距2.3%·人工；帧6127 …** ——每条号码建议到底由哪一帧的哪个框投出来，一眼可对照 LS 翻帧验证。

**其他**
- 诊断面板新增「草稿: #id 更新于 …」行。
- fix_label 依据文案去掉 `<b>` 标签（前端转义后会原样显示，难看）。
- 单测 105 项全过（新增 [20] 数据源一致性 6 项）。

## 2.12.1（当前 · 修 6114 帧误伤）

**起因**：6114 帧的 4 条"疑似误检"全部误伤——
- 2 条 unknown 硬删（那是没认出队别的真人，不是垃圾框）；
- 2 条重叠删：`teamA#25` vs `teamA#3`（差 1.6%）、`teamB#18` vs `teamB#15`（差 2.1%）——**号码都不同的两个框是两个球员叠加**，旧规则却挑一个删。

**修复**
- **unknown 不再无条件硬删**：与其他框一样走"与上一帧强比对"——上一帧同位置有人就不删；上一帧同位置是带号码的框 → 建议**改标签**（unknown → teamB15）而不是删。
- **重叠删只在"同号"时生效**：两个框号码不同 → 两个不同球员（遮挡/站得近），不再提示；一个有号一个没号 → 存疑，交给人眼；只有两个框**标签+号码都相同**才判重复检测。
- 补框配对：上一帧的框可以与本帧 unknown 框按位置配上（unknown 是占着位置的真人），不再提示"补框"造成重复。
- unknown 框不再出现在补号建议里（由删框/改标签接管）。
- 单测 99 项全过（[15] unknown 改写为 3 场景 + 新增 [19] 重叠删收敛 3 项）。

## 2.12.0（当前 · 删框收敛 + 管线排序）

**删框不再刷屏（用户诉求："不要出现那么多疑似误检，其他的我眼睛看一下吧"）**
- **下线"多帧加权投票删"**（旧规则：存在证据权重 < 35% 就提示删 → 每帧都能刷出一大片）。
- 删框现在**只认"与上一帧强比对"**：上一帧该位置（容差 10%，不论什么标签）**一个框都没有** → 才判定误检。
- 两条防误杀保护：
  - **球衣号码唯一标识**：上一帧里存在同队同号（哪怕位置移动 30%）→ 真人在移动，绝不提示删。
  - **位置有人但标签不同** → 那是"改标签"候选（交给 `fix_label`），不再当误检删掉。
- 没有上一帧数据时，用**下一帧**兜底（不会因为在第一帧就误删）。
- 面板底部新增 **「删框:严格/宽松」** 开关（默认严格）：
  - 严格 = 只与上一帧强比对；
  - 宽松 = 额外提示"所有邻帧都没有"的框（兜底，仍比旧规则收敛）。
  - 切换后自动重算当前帧，选择写进 localStorage 会记住。

**管线顺序按业务口径重排：删框 → 补号 → 补框**
- 先定删哪些框，删框定完才统计"哪些框缺球衣号""哪些框要补"。
- 待删的框**不再叠加补号/缺号标记**（以前会出现"这个框建议删除"和"这个框建议补 7 号"同时挂在一条上）。
- 补号撞号保护：投票给的号码若本帧同队已被占用 → 不再补（会造重复号），改为提示人工填号。
- 补框位置若正好压在待删框上 → 不补（避免删了又补自相矛盾）。

**测试**
- 单测 83 → **94 项全过**（新增 [18] 删框收敛 12 项：移动保护 / 改标签分流 / 下一帧兜底 / 严格 vs 宽松 / 待删不补号）。
- 加载自检 4 项全过。

## 2.6.0（当前 · 基线版）

**修复**
- **跳转改为"先拽列表、再查接口"**：以前是等筛选/翻页接口先返回 id 才开始拽，接口一慢列表就不动；现在点「跳转」**列表立刻开始移动**，找到行就点，找不到才去查 task id，最后兜底整页跳转（保证一定能到目标帧）。
- **帧列表滚动容器识别改进**：编辑器界面里有多个可滚动区域，旧逻辑按"最长"挑会挑错（拽到右侧面板）→ 改为按"内部纯数字单元格数量"打分，≥3 个且最多者优先。

**保留（此前已修好的关键项，均已验证）**
- `content.js` 顶层多余 `return;` 导致"脚本加载后整段不执行"→ **已删除**（这是所有"版本对、面板不出"的根因）。
- `bg.js` 全部 `chrome.*` 调用先判存在，不会再因 `chrome.alarms` 缺失而崩溃。
- 编辑器内「应用」= 只在画布上操作（点框→删/填号），**不写接口**，改动由您点 Submit/Update 落库，不会被草稿覆盖。
- 画布标记**默认关闭**（页面干净），面板底部「画布标记:关/开」可切换。
- 补号/改号会填到"点框后底部弹出的号码框"里（点框前后对比找新出现的输入框 + 回车确认）。
- 人工标注号码解析支持 `parent_id` 挂法（此前人工号码全被判缺号）。
- unknown 标签硬规则（直接标删）、缺号必标记，且两者互斥。
- 权重：前一帧主导（人工帧前 0.99 / 机器帧前 0.75）。
- 新增 `test_load.js` 加载自检（真实执行三脚本，断言能跑到末尾）。

**自检状态**：加载自检 4 项通过 · 单元测试 82 项通过。

## 2.4.5（当前交付 · 回滚版）

**回滚内容**
- 版本号回到 2.4.5，manifest 权限回到 `storage / scripting / tabs`（去掉 alarms）。
- 后台脚本 `bg.js` 重写为防御式：`chrome.action`、`chrome.scripting`、`chrome.tabs` 全部先判存在再调用，任一缺失只跳过、不抛错。
- 去掉内容脚本顶部的"重复注入守卫"（改用 DOM 去重：重建前先移除旧的标志/面板），避免任何提前 `return` 导致整段不执行。

**保留的能力**（回滚不影响）

- 建议引擎：补号/改号/补框/删框 + unknown 硬规则 + 缺号必标记（可删框/补号二选一）。
- 权重：前一帧主导（人工帧前 0.99 / 机器帧前 0.75，后侧 0.80 / 0.17）。
- 写入：编辑器里「应用」= 像人一样点框/删框/填号（不刷新、不提交，由您点 Update）；模拟失败自动回退接口写入 + 写完核对。
- 退回：修改历史 + 一键回退到修改前原始数据。
- 数据新鲜度：当前帧 + 前后各 2 帧强制直连平台；改过的帧 10 分钟内不走缓存；平台一有写入清空页面副本。
- 工具栏图标：页面没自动注入时，点图标可手动注入并打开面板。

## 已知限制

1. **机器预测（凉白开）只读**：预测里的框永久存在，"删除"只作用于人工标注。看预测那份自然看不到变化。
2. 同一帧存在多份人工标注时，插件只改当前显示的那份（靠 URL 的 `annotation` 参数判断）。
3. 模拟点击依赖 LS 的 DOM 结构（选区类名、删除按钮、提交按钮），识别不到时会自动回退接口写入。
4. 合成操作不会自动点提交，需您手动点 Update；模拟失败时改用接口写入，此时页面需 F5 才能看到。
